# Digital twin: machine model conventions

Every model in `public/models/` follows these rules. The viewer reads node
names and node transforms — it never hardcodes coordinates per machine type.

## Axes and units

* Metres. Y up. **X is the shaft axis**, drive end toward +X. Z is the horizontal cross-axis.
* Origin sits at floor level, centred on the machine.
* A model is authored at its real physical size, so the viewer's auto-fit works without per-type tuning.

## Node names

| Pattern | Meaning |
|---|---|
| `SNS_<LOCATION>_<H\|V\|A>` | Sensor mounting point. **Local +Y points along the measurement axis.** |
| `BRG_<LOCATION>` | Bearing anchor, at the bearing centre. |
| `CASING_*` | Meshes that fade in x-ray mode (housings, covers, guards, volutes). |
| `ROTOR` | Parent node for everything that rotates. Spinning it rotates about local X. |

`<LOCATION>` uses underscores: `MOTOR_DE`, `FAN_NDE`, `GB_HSS_DE`, `MAIN_BRG`.
Axis letters are H horizontal (+Z), V vertical (+Y), A axial (±X).

**Do not name sensor nodes CH1…CH6.** Channel numbers are positional and change
when a sensor is deleted. The frontend adapter builds the node name from
`mounting_location` + `orientation` and keeps the CH number only as the display
label on the chip.

Place anchors on the **node transform**, not baked into mesh vertices. A node
whose transform is identity gives the viewer the origin, not the anchor.

## Adapter mapping

```
mounting_location  "Bearing Housing DE"  ->  MOTOR_DE | FAN_DE | PUMP_DE | ...
orientation        "Horizontal"          ->  H
node name          SNS_FAN_DE_H
```

Keep the location half of that mapping in one registry keyed by machine type,
so adding a machine type is a data change.

## Replacing a model

These are parametric stand-ins, generated by `models/build_models.py`
(Python + trimesh). They are correct in proportion, layout and naming, but they
are not a specific manufacturer's machine. When a real scanned or CAD-derived
model arrives:

1. Confirm the axes and units above.
2. Rename its nodes to match the table.
3. Move anchors onto node transforms with +Y along the measurement axis.
4. Drop it in `public/models/<type>.glb`. No viewer code changes.

Only the model file changes — the adapter, the anchors and the x-ray layer all
keep working.
